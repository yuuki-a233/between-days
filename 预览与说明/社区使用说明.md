# 日常之间 · 本地社区测试版

米白与雾蓝的生活创作杂志，支持代码、作品、笔记、日常和交流。

## 马上体验（Windows）

1. 将整个文件夹解压到可写位置，双击 `启动本地测试.cmd`。首次启动会下载依赖，需要联网，后续启动复用已安装依赖。
2. 保持启动窗口打开，在浏览器访问 http://localhost:3100 。如果本机已有 Codex 随附的 Node.js 24.15+，启动脚本会尝试使用它；否则需安装 Node.js 24.15 或更高版本。
3. 点击登录，选择站长、管理员或普通用户，获取验证码。
4. 在新标签页打开「测试收件箱」，复制本次随机验证码，返回登录页填写。

| 测试身份 | 邮箱 | 可以体验什么 |
| --- | --- | --- |
| 站长 | owner@between-days.test | 审批发布、设置管理员、内容与用户管理 |
| 管理员 | admin@between-days.test | 审批发布、内容与用户管理 |
| 普通用户 | member@between-days.test | 评论、回复、点赞、收藏、申请发布资格 |

测试验证码有效期 5 分钟，每次随机生成，使用后失效；没有固定密码或万能验证码。测试收件箱是开发专用工具，能查看测试邮件，切勿将开发服务器开放到公网。

如果 3100 端口已在使用，请直接打开现有地址，或关闭本项目原来的启动窗口后再启动。需要改端口时，复制 `.env.example` 为 `.env.local`，同时配置 `PORT` 和 `APP_URL`。

## 功能与权限

- 作品、笔记和日常分栏展示，可搜索、按分类筛选、分页浏览；作者有独立主页。
- 封面可选。支持 Markdown 正文、代码块、源码或 ZIP 项目包、Markdown/TXT、图片、PDF、Word、Jupyter 等附件（20 MB 以内），文本和 Markdown 可在线预览。
- 个人资料支持昵称、介绍与头像。收藏清单仅本人可见。
- 普通用户可以评论、回复、点赞、收藏；发布需申请，由站长或管理员批准。
- 管理员可直接发布、审批或撤销发布资格、下架内容、停用账号、处理举报；只有站长可以设置管理员。
- 作者只能编辑自己的内容。撤销发布资格后不能新增或编辑，仍可删除自己的内容。
- 下架或删除内容后，其附件同步不可访问；若同一附件仍被另一篇可见内容使用，则仍可从该内容访问。
- 管理后台的操作留有记录。默认只允许三个测试邮箱及管理员新增的测试邮箱登录。

## 数据保存

数据保存在 `data/community.sqlite`，附件保存在 `data/uploads/`。关闭窗口、重启应用不会清空数据。

请保留整个 `data/` 目录。源码包不包含本次开发产生的数据、邮件或会话密钥，首次启动会生成独立数据。

备份（终端进入本项目目录）：

```bash
node scripts/backup.ts
```

默认生成 `backups/日期时间/`，包含数据库快照、上传文件和本地会话密钥。备份具有敏感性，不要公开分享。

恢复时先停止应用，将备份中的 `community.sqlite`、`uploads/` 和 `.runtime.json` 放入一个新的数据目录，再通过 `DATA_DIR` 指向该目录启动。不要覆盖正在运行的数据库，也不要把旧的 `-wal`、`-shm` 文件带入新目录。

## 开发与检查

```bash
node vendor/npm/bin/npm-cli.js ci --no-audit --no-fund
node scripts/launch.mjs dev
node --test tests/core.test.ts
node tests/integration.mjs
node node_modules/typescript/bin/tsc --noEmit
node scripts/build.mjs
```

集成测试需要本地开发服务正在运行，且会操作三个专用测试身份并创建 `QA · ` 前缀的测试内容。完成后可运行 `node tests/reset-demo.ts` 清理 QA 内容并重置三种测试身份的发布权限；不会清空全部数据库。

## Ubuntu 与正式配置

请阅读 `deploy/Ubuntu部署说明.md`。现在只提供部署包，不连接或修改你的服务器，不购买域名，不公开上线。

生产运行会强制要求真实站长邮箱、SMTP、HTTPS 地址与独立密钥；禁止启用开发测试收件箱，开发测试身份不会自动获得生产权限。
